# Правила роботи в команді

1. **У main напряму не пишемо.** Усі зміни — через гілку і Pull Request.
2. **Одна задача — одна гілка — один Issue — один PR.**
3. **Назви гілок:** `feature/що-робимо` (нова можливість), `fix/що-виправляємо` (виправлення).
   Приклади: `feature/save-to-file`, `fix/empty-input`.
4. **Повідомлення комітів** — коротко, наказовим способом, про зміст:
   «Додати збереження витрат у CSV», «Виправити помилку при порожньому введенні».
   Погано: «зміни», «123», «фффф».
5. **Перед початком роботи:** `git switch main` і `git pull`.
6. **Перед PR:** запустити програму й переконатися, що вона працює.
7. **PR зливає не автор.** Колега переглядає зміни (Files changed), залишає коментарі
   і натискає Approve. Лише після цього — Merge.
8. **В описі PR** пишемо `Closes #номер`, щоб Issue закрився сам.
9. **Конфлікт — не катастрофа:** `git pull origin main`, прибрати маркери `<<<<<<<`,
   `=======`, `>>>>>>>`, залишивши потрібний код, запустити програму, `git add`, `git commit`, `git push`.
